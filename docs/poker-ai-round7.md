# 德州人机第七轮：采样次数、线上包拆分和逐决策评估

本轮不新增策略模型，做三件事：试验把服务器人机的胜率采样从 100 次改为 600 次（确认实验未通过，已改回 100 次）；把实验模型从生产策略文件拆出去；新增一个只在两版策略选择不同时才比较的评估脚本。生产策略的决策规则不变。

后两项是代码隔离和测量工具，本身不会让人机变强。采样次数由第四节事先定好规则的确认实验决定：未通过，服务器维持 100 次。

## 一：采样次数

生产策略的每个决策都依赖蒙特卡洛胜率估计。服务器（朋友房间的人机）只采样 100 次，胜率标准误约 5%，已经接近决策阈值之间的差距；单人练习在 Web Worker 中采样 1200–1800 次。

用 v127 对自身做单变量对照：两边策略、性格和发牌完全相同，只改挑战者的采样次数，对手固定 100 次。同牌、座位轮换、每手重置 100BB。表中「全下校正」把进入全下摊牌后的实际公牌换成剩余公牌上的期望筹码，只降低方差，不改变期望。

|挑战者 vs 对手|桌型|手数|BB/100|95% 区间|全下校正 BB/100|95% 区间|
|---|---|---:|---:|---|---:|---|
|400 vs 100|双人|20000|+4.59|[-11.91, +21.10]|+6.40|[-8.05, +20.84]|
|600 vs 100|双人|20000|+7.18|[-8.97, +23.32]|+5.99|[-8.22, +20.19]|
|1200 vs 100|双人|20000|+17.43|[+1.14, +33.73]|+17.05|[+2.94, +31.16]|
|600 vs 100|四人|10000|+42.38|[+14.51, +70.24]|+29.30|[+4.89, +53.71]|
|1200 vs 100|四人|10000|+11.87|[-16.20, +39.95]|+17.88|[-6.76, +42.51]|

五组点估计全部为正，其中两组区间不含 0。但这五组是同时比较的多个配置，从中挑出区间不含 0 的一组存在偶然性；四人桌 1200 次的估计还低于 600 次。因此这一节只算初步正向信号，不能当成已验证的增强。全下校正使标准差下降约 12–13%，相当于多出约 30% 的有效手数。

耗时（本地 Node，单次决策）：

|采样|双人 平均 / p95 / 最大|六人 平均 / p95 / 最大|
|---:|---|---|
|100|0.69 / 1.65 / 2.52 ms|0.79 / 1.57 / 2.14 ms|
|600|2.09 / 2.81 / 4.37 ms|2.97 / 4.33 / 6.93 ms|
|1200|3.95 / 4.76 / 5.07 ms|5.86 / 9.18 / 12.88 ms|

服务器每次房间 tick 只执行一个人机决策，且人机行动间隔至少 1.05 秒。考虑到 Workers 的 CPU 时间限制和线上机器可能慢于本地，若采用更高采样，上限取 600 次（`server/rooms.mjs` 中的 `SERVER_POKER_SAMPLES`）。单人练习的采样次数不变。

先验上也不能假定更多采样一定更好：各性格的阈值和温度参数是在 100 次采样的噪声下调出来的，噪声本身起了一部分随机化作用；胜率更准后，打法可能更确定，也可能更容易被针对。

## 二：实验模型移出线上包

第六轮之后，`dist/strategy.mjs` 直接 import 了 range、planning、river-value、multiway-value 四个实验模块。虽然默认全部关闭，它们连同约 182KB 的概率表被打进了大厅首屏的 `app` 包（261KB，PERFORMANCE.md 中记录的首屏 JS 为 61KB），并随 `ai-worker.mjs` 加载。

拆分后：

- `dist/strategy.mjs`（生产）不再 import 任何实验模块，只保留可选的 `lab` 钩子：`rangeOf`（公开范围）、`before`（河牌价值 / 双人搜索）、`raiseValue`（多人全下估值）、`collectWorlds`。不传 `lab` 时代码路径与拆分前完全相同。
- `dist/strategy-lab.mjs`（实验入口）接收与原来相同的参数（`rangeModel`、`lookahead`、`riverValue`、`multiwayAllIn`），把实验模型接到这些钩子上。所有 `benchmark-poker*.mjs` 脚本和 `tests/poker-planning.test.mjs` 改为引用它。核心决策逻辑只有一份，不会出现两份代码分别演化。

验证：

- 默认、`public` 范围、双人搜索、河牌价值、多人全下五种配置，在 2 人和 4 人桌上逐个决策比较拆分前后的输出（动作、加注额、胜率、EV），共约 3900 个决策，全部一致（搜索预算放宽到 1000ms，排除计时回退的影响）。
- 生产默认、实验入口默认与 v127 固定对照逐个决策一致（新测试 `tests/poker-strategy-split.test.mjs`）。
- 构建后大厅 `app` 包 261.2KB → 79.0KB，其中实验代码 182.1KB → 0。
- 德州相关测试、房间、服务端和性能测试共 69 项：66 项通过；3 项失败（语音控件、3D 头顶标签位置、底池遮挡）在拆分前的原代码上同样失败，与本轮改动无关。

## 三：逐决策评估脚本

完整牌局 A/B 对照中，绝大多数手牌两版策略的动作完全相同，置信区间主要由发牌运气决定；第六轮 1200 手中只有 5 个决策真正被改变。

`scripts/eval-poker-decisions.mjs` 由现行策略 A 正常打牌。被评估座位每次行动时，同时询问 A 和 B；两者不同时，从同一状态分出两条线：A 线执行 A 的动作并继续用 A，B 线执行 B 的动作并继续用 B，其余座位用旧人机，各自打完整手。未来公牌从未见过的牌中重新发，同一次模拟的两条线共用同一组公牌和同一组随机数流。重复多次，取两条线的筹码差平均。对手私牌固定为真实发牌，不进入任何策略的输入。

检查：A 与 B 相同时，271 个决策中分歧 0 次、收益 0。

随机流：两版策略各用两条独立的随机流，一条只用于胜率采样（`decide` 的可选参数 `equityRng`），一条用于动作混合（`rng`），A 和 B 使用相同的种子。`decide` 原本用同一个 `rng` 先采样再混合动作，采样次数一变，消耗的随机数不同，后面的混合抽签也随之全变，会产生大量并非由胜率估计引起的分歧。不传 `equityRng` 时行为与之前完全相同。

只在每手第一次分歧处分线：随机流对齐后，A 和 B 在第一次分歧前走完全相同的路线；从那里起两条线各自用自己的策略打完，差值就是这一手换用 B 的收益。之后再出现的分歧只计数、不再分线，否则会重复计算 B 的后续选择。

示例：第五轮河牌动作价值（`{"rangeModel":"public","riverValue":true}` 对比 `{"rangeModel":"public"}`），双人桌 20000 手、每个分歧 24 次模拟：

- 25367 个决策中分歧 240 次，涉及 232 手，第一次分歧全部在河牌；
- B 相对 A：-0.63 BB/100，95% 区间 [-4.09, +2.84]；受影响的每手平均 -0.54 BB；
- 运行 78 秒。

结论与第五轮一致：未确认收益。同为 20000 手双人桌，完整牌局对照（第一节）的区间半宽约 ±16 BB/100，这里约 ±3.5，约窄 4.6 倍，即达到同样精度所需手数约少 20 倍。

（本节最初的版本共用一条随机流，并在同一手的每次分歧处都分线，会把 B 的后续选择重复计算；当时报告的 +0.61 [-2.60, +3.82] 已由上面的数字替换。）

限制：单手视界、每手重置筹码；对手为 v127 家族随机性格；只评估被选中的一个座位；模拟次数有限时，每个分歧的估计仍有方差（已计入区间）。它测的是「在这些局面改用 B」的收益，不是对真人的收益。

## 四：采样次数的确认实验（规则先于结果写定）

规则写定时间：2026-10-09 23:08（美东），写定后才开始运行这组种子。

- 唯一比较：四人桌，A = 现行 100 次采样，B = 600 次采样；其余参数相同。被评估座位按手轮换，其余三席为 v127 固定版本（100 次采样）。
- 方法：`scripts/eval-poker-decisions.mjs`（独立随机流、只在每手第一次分歧处分线），40000 手，每个分歧 24 次模拟，种子偏移 31000000。该种子段此前未用于任何实验。估算耗时用的 300 手试跑（偏移 5000000）不计入。
- 判定：B 相对 A 的 95% 区间下限 > 0，则保留 `SERVER_POKER_SAMPLES = 600`；否则改回 100。
- 不根据结果调整参数、追加手数或改换比较组；双人桌和其它采样值本轮不再比较。

结果（40000 手，运行 552 秒）：

- 52959 个被评估决策中分歧 1289 次，涉及 1198 手；第一次分歧在翻前 228、翻牌 654、转牌 222、河牌 94 手；
- B（600 次）相对 A（100 次）：+1.93 BB/100，95% 区间 [-1.99, +5.84]；受影响的每手平均 +0.64 BB。

区间下限 < 0，**未通过**。按规则把 `SERVER_POKER_SAMPLES` 改回 100。

解读：区间半宽约 ±3.9 BB/100，远窄于第一节完整牌局对照的 ±24；若 600 次的收益存在，量级也只有每 100 手几个 BB，第一节四人桌的 +29.30 很可能主要是噪声加上从多组配置中挑选的结果。这个结论只针对 v127 人机之间的模拟，不代表真人对局。

## 下一步建议

新的策略实验先用逐决策评估筛选，确认在分歧局面上有正收益后，再用完整牌局对照确认没有整体退化。对手池建议加入几种模拟真人常见倾向的固定规则玩家（跟注站、疯狂加注、只打大牌、偏爱最小加注），并把「对最容易剥削本策略的对手的输率」作为第二指标。
