# 德州人机第八轮：模拟真人的对手池与加注弃牌率模型

## 一：模拟真人常见毛病的对手池

`tests/fixtures/poker-human-opponents.mjs` 新增五种规则型对手，只看自己的快照（自己的牌、公牌、公开下注），用于评估，不进入线上：

- 跟注站：大多数牌都玩，进了底池几乎不弃牌，很少主动下注；
- 疯子：任何牌都频繁加注、超池下注；
- 石头：只玩强起手牌，翻后只用强成牌继续，有牌就价值下注；
- 最小加注党：中等牌就喜欢最小加注，跟注偏松，遇到大注放弃；
- 不中就弃：翻前跟得宽，翻后没对子没听牌就弃，中了才下注。

`scripts/benchmark-poker-human-pool.mjs` 测一个策略分别对每种对手（三席同类）的收益；`scripts/eval-poker-decisions.mjs` 新增第 7 个参数选择对手池（`v127`、`human` 轮换五种，或单一类型）。

现行线上策略（v127）四人桌、每类 2000 手、100 次采样（偏移 0）：

|对手|BB/100|95% 区间|
|---|---:|---|
|跟注站|+492.2|[+352.6, +631.8]|
|疯子|+458.5|[+265.4, +651.5]|
|最小加注党|+416.5|[+260.0, +573.0]|
|不中就弃|+135.2|[+5.1, +265.3]|

规则对手本身很容易被剥削，前三类数字大是预期内的。值得注意的是石头：现行策略对它基本赢不到钱。这类对手在旧人机互打的测试中不存在，以前的评估测不出这个弱点。

## 二：加注弃牌率模型（实验，默认关闭）

`strategy.mjs` 中加注候选的全员弃牌概率原为固定公式（`.16+ratio*.21+位置/范围/阻断项…`，再按人数取幂），与对手的公开行动无关。新增 `lab.foldRate` 接入点（不传时行为不变），实验实现 `dist/poker-fold-model.mjs`：

- 对每个仍在场的对手，用 `opponentRange`（只用公开行动）得到手牌范围，按牌力档位和听牌汇总权重；
- 用已训练的回应模型 `responseRates`，按该对手面对这次加注的价格、加注后底池、位置和本街加注次数，得到每个档位的弃牌概率，再按范围加权；
- 各对手弃牌率相乘得到全员弃牌概率；有对手已全下时为 0，与原规则一致。

只替换弃牌率这一项；被跟注后的胜率估计、加注候选生成、混合抽签都不变。实验入口：`strategy-lab.mjs` 的 `foldModel:true`。

单次决策耗时（本地 Node，每次清空范围缓存的最坏情况，100 次采样）：双人 平均 3.31 / p95 11.44 / 最大 18.35 ms，六人 2.24 / 8.31 / 21.24 ms；关闭时约 0.7 / 1.5 / 3 ms。

## 五：按对手类型细分（探索性，确认之后补做）

四人桌、三席同类规则对手、每类 4000 手、种子偏移 52000000：

|---|---:|---:|---|

|最小加注党|363|+52.10|[+22.09, +82.11]|

收益主要来自很少弃牌的对手：模型从公开行动看出对方范围宽、跟注多，减少无效诈唬、增加价值加注。对石头只有小幅改善，现行策略对石头赢不到钱的问题（第一节）大部分仍在，原因可能在跟注/弃牌决策而非加注，值得单独研究。对疯子几乎没有可加注的局面，所以没变化。

## 六：启用前需要决定的事

- 包体积：启用需要把 `poker-range.mjs`、`poker-response.mjs` 和约 145KB 的 `poker-response-data.mjs` 带进生产（服务器和单人练习的 Worker）；它们目前已从生产包移出（第七轮）。
- 耗时：每次决策平均多 2–3 ms，p95 约 8–11 ms，最坏约 21 ms（本地，冷缓存）。服务器每次 tick 只算一个人机决策。
- 只确认了 100 次采样（服务器配置）；单人练习用 1200–1800 次，未单独验证。
- 对手模型仍是用 v127 的行为训练的，真人的弃牌习惯可能不同。
